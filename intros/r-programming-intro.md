# R Programming: Introduction to All Topics

This document is a guided tour of the 6 sections in the R Programming knowledge base — a production-focused reference for statisticians, data scientists, and R engineers moving from analysis scripts toward reproducible, production-quality tools. The content spans beginner language foundations through expert-level engineering, covering R the language, the Tidyverse, ggplot2, classical and Bayesian statistics, machine learning, and advanced R (metaprogramming, OOP, C++, web apps, and REST APIs). Every page pairs conceptual explanation with runnable R, KaTeX math, Mermaid diagrams, and interactive React demos.

**Suggested learning path:** Core R → Tidyverse → ggplot2 → Statistical Analysis → Machine Learning → Advanced R

## 01. Core R

R is a vectorised, dynamically-typed language built by statisticians for statistical computing; this section lays the language foundations that everything else depends on — the type system, the environment model, and the performance mechanics that explain why idiomatic R looks the way it does.

**What's covered:**

- **R Syntax & Vectors** — R has no scalar type: `1L` is a length-one integer vector and every operation is vectorised into C-level loops. The six atomic types (logical/integer/double/character/complex/raw) and their internal SEXPTYPEs; the coercion hierarchy logical ≺ integer ≺ double ≺ complex ≺ character; typed missing values (`NA_real_`, `NA_integer_`, `NA_character_`) and how `NA` propagates through arithmetic (`NA == NA` is `NA` — use `is.na()`); vector recycling (silent when lengths are multiples, warning otherwise); `typeof()` (storage) vs `class()` (S3 dispatch) vs `storage.mode()`; attributes (`names`, `dim`, `class`) that turn a bare vector into a matrix or factor with no change to storage; `seq_along()`/`seq_len()` over the `1:length(x)` empty-vector footgun.
- **Data Structures & Control Flow** — lists as `VECSXP` pointer arrays and the `[` vs `[[` "train car" distinction; matrices/arrays as vectors + a `dim` attribute in column-major order (prefer `colSums`/`rowSums`/`%*%`/`crossprod` over element-wise apply); data frames as named lists of equal-length vectors, with tibbles removing the historical `stringsAsFactors` coercion; factors as integer codes + `levels`; scalar `if` vs vectorised `ifelse` (which evaluates both branches — `pmax` is faster); `for`/`while`/`repeat`, `next`/`break`, `switch`; the Lisp-style condition system — `tryCatch` (unwinds the stack, returns a value) vs `withCallingHandlers` (stays on the stack, `invokeRestart("muffleWarning")`); pre-allocate to avoid O(n²) `c()`-growth; `vapply` over `sapply` in production.
- **Functions & Environments** — first-class functions and the R 4.1 lambda `\(x)`; lexical scoping (name lookup follows the *definition* environment, not the call site); environments as mutable hash maps (`new.env`, `parent.env`, `<<-` super-assignment); closures as functions paired with a frozen enclosing environment (factory/counter patterns); `match.arg` for validated choices, `missing()` vs `NULL`, `...` forwarding with `...length()`/`...elt()`/`..1`; `on.exit(add = TRUE)` as R's `finally`; `Recall` for recursive anonymous functions.
- **Package Development** — the `devtools`/`usethis` loop (`create_package` → `load_all` → `test` → `document` → `check`); `DESCRIPTION` semantics (`Imports` installs at runtime, `Suggests` is optional, never abuse `Depends`); Roxygen2 tags (`@param`/`@return`/`@export`/`@importFrom`) that regenerate `NAMESPACE` and `man/*.Rd` — never hand-edit `NAMESPACE`; `testthat` 3rd edition with `expect_snapshot`; `covr`/`lintr`/`styler`/`spelling` in CI; the CRAN checklist (`R CMD check --as-cran`, win-builder, rhub, examples under 5s, no global side effects).
- **R Performance & Profiling** — measure first: `profvis` flame graphs, `Rprof`/`summaryRprof` on headless servers, `bench::mark` (prefer `median`, watch `mem_alloc` and `n_gc`); copy-on-modify revealed by `tracemem()` and `lobstr::ref()`; `lobstr::obj_size` counts shared memory correctly where `object.size` overcounts; vectorisation replaces the ~100 ns/iteration R loop with ~1–5 ns/element C loops via `cumsum`/`diff`/`tabulate`/`vapply`; `data.table` `:=` in-place mutation and `setkey` O(log n) lookups (2–5× over dplyr on large data); the 10× rule for reaching for Rcpp.

**Key mental models:** Everything is a vector and vectorisation is the performance model — push loops into C before anything else. Objects are copy-on-modify (efficient to read, doubles memory on write), which is exactly why closures and environments are powerful. `typeof()` reveals storage while `class()` drives dispatch. Profile before optimising, and only then reach for `data.table` or Rcpp.

## 02. Tidyverse

The Tidyverse is a cohesive family of packages sharing one philosophy — tidy data (variable = column, observation = row, value = cell), data-frame-in/data-frame-out APIs, and the pipe (`|>` / `%>%`) — that turns R into a high-level data query language and functional pipeline in one.

**What's covered:**

- **dplyr Data Manipulation** — the five verbs (`filter`/`select`/`mutate`/`summarise`/`arrange`) chained with the pipe; `group_by` + `summarise` with `across()` and tidy-select helpers (`starts_with`/`ends_with`/`contains`/`matches`/`where`/`all_of`/`any_of`); window functions (`row_number`, `rank`, `dense_rank`, `percent_rank`, `ntile`, `lag`/`lead`, `cumsum`, `cummean`); `slice_max`/`slice_min`/`slice_sample`/`slice_head`; SQL-style joins (left/inner/right/full) plus the filtering joins `semi_join`/`anti_join`; `case_when`/`case_match`; tidy evaluation with `{{ }}` embracing and `.data[[col]]`.
- **tidyr Reshaping** — the three tidy-data rules; `pivot_longer`/`pivot_wider` (with `names_pattern`, `names_transform`, `values_fn`, `values_fill`); `nest`/`unnest` list-columns for per-group modelling (`mutate(mod = map(data, \(d) lm(...)))`); `unnest_wider` vs `unnest_longer`; the safer `separate_wider_delim`/`separate_wider_regex` (tidyr 1.3+) over legacy `separate`; `unite`; `complete` to make implicit missingness explicit; `fill` for forward/backward carry.
- **stringr & forcats** — the consistent, vectorised `str_*(string, pattern)` API — `str_detect`/`str_starts`/`str_count`/`str_replace(_all)`/`str_extract(_all)`/`str_split`/`str_match`; PCRE regex (character classes, quantifiers, anchors, capture groups, lookaheads); `str_glue` interpolation and `str_pad`/`str_trunc`/`str_wrap`; forcats `fct_reorder` (the single highest-impact function — meaningful ggplot2 ordering instead of alphabetical), `fct_lump_n`, `fct_relevel`, `fct_recode`, `fct_collapse`, `fct_infreq`.
- **lubridate Time Handling** — parsers named for component order (`ymd`/`mdy`/`dmy`/`ymd_hms`) that auto-detect separators and return `NA` on failure; accessors (`year`/`month`/`wday`/`yday`); the crucial Duration (exact seconds) vs Period (calendar units) vs Interval (`%--%`) distinction; the `months(1)` → `NA` trap and `%m+%`/`%m-%` month-safe arithmetic; `POSIXct` as seconds-since-epoch with time zone as a display attribute — `with_tz` (relabel, same instant) vs `force_tz` (re-anchor); `floor_date`/`ceiling_date` for time-series binning.
- **purrr Functional Programming** — type-stable mapping (`map` → list, `map_dbl`/`map_int`/`map_chr`/`map_lgl` error rather than silently coerce); `map2`/`pmap` for parallel inputs and `imap` for index/name; `walk` for side effects; the failure-handling adverbs `safely`/`possibly`/`quietly`; `reduce`/`accumulate` folds (`reduce(list_of_dfs, left_join, by = "id")`); predicates `keep`/`discard`/`compact` and `every`/`some`/`detect`; the same `\(x)` lambda works in `map_*` and `dplyr::across()`.

**Key mental models:** Tidy data plus consistent data-frame-in/data-frame-out APIs plus the pipe make the whole stack read like a left-to-right sentence. Reach for `{{ }}` embracing (symbols) and `.data[[ ]]` (strings) to write safe data-masking helper functions. Prefer type-stable `map_*` and vectorised verbs over explicit loops, and store timestamps in UTC — converting only for display.

## 03. ggplot2

ggplot2 implements Wilkinson's Grammar of Graphics: every chart is composed from independent components stacked with `+`, so any chart type comes from the same grammar and edits are additive rather than rewrites.

**What's covered:**

- **Grammar of Graphics** — the seven components (data, aesthetics, geoms, stats, facets, coordinates, theme); `aes()` mapping columns to visual channels (`x`, `y`, `colour`, `fill`, `size`, `shape`, `alpha`, `group`) with global vs layer-local scope, and constants set *outside* `aes()`; `+` as the `+.gg` S3 method (order affects layer draw order, not scale resolution); every geom's default `stat` (`stat_count`/`stat_bin`/`stat_identity`); position adjustments (`dodge`/`fill`/`stack`/`jitter`); `facet_wrap` (one variable) vs `facet_grid` (two-way matrix) with `scales = "free"`; `%+%` to swap a plot's dataset.
- **Geometric Objects** — the 40+ geom library: `geom_point` (shape codes 21–25 with separate `colour` border and `fill`), `geom_line`/`path`/`step`, `geom_bar` (counts) vs `geom_col` (pre-computed), `geom_histogram`/`geom_density` with `after_stat(density)`, `geom_boxplot` (Tukey's five-number summary, Q₁ − 1.5×IQR / Q₃ + 1.5×IQR fences) layered under `geom_violin`, `geom_smooth` (`lm`/`loess`/`gam`), `geom_tile`/`geom_raster` heatmaps, `geom_ribbon`/`geom_area`, `geom_text`/`geom_label`.
- **Scales & Coordinates** — the `scale_<aesthetic>_<type>()` naming pattern with core args `limits`/`breaks`/`labels`/`expand`; log/sqrt transforms and date scales; the three colour families — sequential (`scale_colour_viridis_c`, perceptually uniform and colour-blind-safe), diverging (`scale_colour_gradient2(midpoint = 0)`), qualitative (`scale_*_brewer`, `scale_*_manual`); `scale_size_area` (maps to area, not radius, for honest bubbles); `coord_cartesian` zoom (clips without dropping data) vs scale `limits` (drop before the stat runs — matters for smoothers); `coord_flip`/`coord_polar`/`coord_sf`; `scales::oob_squish`.
- **Themes & Customization** — the element hierarchy (`element_text`/`element_line`/`element_rect`/`element_blank`) with parent→child inheritance; six complete themes (`grey`/`bw`/`classic`/`minimal`/`void`/`dark`) and `theme_set()` for a session default; `theme()` overrides (`legend.position`, `panel.grid.minor = element_blank()`); custom Google fonts via `showtext` (`font_add_google` + `showtext_auto`); `guides()` (`guide_colourbar` continuous vs `guide_legend` discrete); `ggsave(dpi = 300, device = cairo_pdf)` for print-ready vector output.
- **Extensions & Patchwork** — patchwork's `+`, `/`, and `|` operators with `plot_layout(guides = "collect")` and `plot_annotation(tag_levels = "A")`; gganimate `transition_*`/`enter_*`/`exit_*` (the `group` aesthetic identifies object identity across frames); `plotly::ggplotly` for pan/zoom/hover; ggridges `geom_density_ridges`; ggrepel `geom_text_repel` collision avoidance; writing extensions via the `ggproto` prototype OOP system (inherit from `Geom`, implement `draw_panel` returning a grid `grob`).

**Key mental models:** A plot is layers over a coordinate system, so a change means swapping one component and keeping the rest. Map variables inside `aes()`; set constants outside it. Prefer perceptually-uniform viridis and `coord_cartesian` zoom for accessible, undistorted charts, and learn the `scale_<aesthetic>_<type>()` pattern rather than memorising individual functions.

## 04. Statistical Analysis

Statistical modelling is R's original reason for existence, and its base functions for testing, regression, and distributions remain unmatched; this section walks the full workflow from classical frequentist inference through Bayesian modelling, time series, and survival analysis, always pairing theory with implementation and assumption-checking.

**What's covered:**

- **Hypothesis Testing** — H₀/H₁ and correct p-value semantics (probability of the observed statistic or more extreme under H₀ — *not* P(H₀ true)); Type I (α) vs Type II (β) errors and power = 1 − β; `t.test` (Welch by default, `var.equal`, `paired`) with Wilcoxon rank-sum/signed-rank when normality fails; `chisq.test` vs `fisher.test` (expected cell counts < 5); Cohen's d and rank-biserial effect sizes via the `effectsize` package; `pwr` power analysis (fix any three of n/d/α/power); Bonferroni (family-wise error) vs Benjamini–Hochberg (false discovery rate) via `p.adjust`.
- **ANOVA & Regression** — ANOVA and regression as two views of the general linear model y = Xβ + ε; one/two-way `aov` with `TukeyHSD` post-hoc and interaction plots; `lm` with the OLS estimator β̂ = (XᵀX)⁻¹Xᵀy and the four `plot(fit)` diagnostics (residuals-vs-fitted, Normal Q-Q, scale-location, Cook's distance) plus Durbin–Watson; centering predictors before interaction terms; `glm` link functions — logistic (odds ratios via `exp(coef)`), Poisson, Gamma; `lme4` mixed models (random intercept/slope, REML for estimation vs ML for comparison); `AIC`/`BIC` and likelihood-ratio tests for selection.
- **Bayesian Analysis** — Bayes' theorem P(θ|y) ∝ P(y|θ)·P(θ); prior types (flat, weakly-informative, strongly-informative) and conjugate pairs (Beta–Binomial, Normal–Normal, Gamma–Poisson); `brms`'s `lm`/`lmer`-style formula interface compiling to Stan; credible intervals as direct probability statements about the parameter (unlike frequentist CIs); MCMC convergence diagnostics — R̂ < 1.01, Bulk-ESS/Tail-ESS ≥ 400, "fuzzy caterpillar" trace plots; posterior predictive checks (`pp_check`); HMC/NUTS over random-walk Metropolis; Stan's `data`/`parameters`/`model` blocks.
- **Time Series** — the tidyverts stack: `tsibble` (explicit `index` + optional `key`, `has_gaps`/`fill_gaps`), `fable` (fit ETS/ARIMA/TSLM together, auto-selected by AIC, `forecast`/`autoplot`), `feasts` (batch feature extraction — trend/seasonal strength, spikiness); ETS decomposition (Error-Trend-Seasonality, additive vs multiplicative); ARIMA(p,d,q)(P,D,Q)ₘ via the backshift operator with unit-root tests (`unitroot_kpss`/`unitroot_ndiffs`); STL/Loess decomposition; accuracy metrics (MASE, RMSSE) and Ljung–Box white-noise residual checks.
- **Survival Analysis** — censoring (right/left/interval, assumed non-informative); the survival function S(t) = exp(−H(t)) and the hazard h(t); the Kaplan–Meier step estimator with the log-rank test (`survdiff`); the semi-parametric Cox model (`coxph`, hazard ratios via `exp(coef)`) and the proportional-hazards assumption tested with `cox.zph`/Schoenfeld residuals; time-varying covariates restructured into (start, stop] intervals via `tmerge`; parametric `survreg` (Weibull, log-normal); `survminer::ggsurvplot`.

**Key mental models:** Choose the test from the data structure (outcome type × number of groups × paired?) and always report effect sizes alongside p-values. Frequentist intervals describe the procedure; Bayesian credible intervals describe the parameter. Never trust a model before checking its assumptions — regression diagnostics, R̂ and ESS, proportional hazards, and white-noise residuals are all gates, not afterthoughts.

## 05. Machine Learning in R

R offers a mature, rigorous ML ecosystem that is especially strong for tabular data, honest cross-validation, and interpretation; this section covers the end-to-end workflow through two unifying frameworks (tidymodels and caret), the dominant algorithms, and post-hoc explanation.

**What's covered:**

- **tidymodels Workflow** — one pipe-friendly grammar across algorithms: `rsample` (`initial_split(strata = )`, `vfold_cv`), `recipes` (`step_impute`/`step_normalize`/`step_dummy`/`step_zv`/`step_corr`, `prep`/`bake`, fitted only on training folds to prevent leakage), `parsnip` (model type decoupled from engine via `set_engine`/`set_mode`, `tune()` placeholders), `workflows` (bind recipe + model), `tune` (`tune_grid` over resamples, `collect_metrics`, `select_best`, `finalize_workflow`, `last_fit` for the single honest test estimate), `yardstick` (rmse/rsq/roc_auc/f_meas).
- **caret & Cross-Validation** — one `train()` call over 200+ algorithms where only `method` changes; `trainControl` declared once and shared for identical fold splits (`cv`/`repeatedcv`/`boot`/`LOOCV`/`timeslice`); the CV estimate CVₖ = (1/k) Σ L(yᵢ, f̂⁻ⁱ(xᵢ)); `tuneLength` (auto grid) vs `tuneGrid` (explicit `expand.grid`); `resamples()` for statistically paired model comparison on the same folds; `varImp()` model-agnostic importance; `preProcess` inside `train` to avoid leakage.
- **Gradient Boosting (xgboost)** — sequential ensembles fitting pseudo-residuals (vs parallel bagging in random forests); the regularised objective ℒ = Σ l(y, ŷ) + Ω(f) with Ω(f) = γT + ½λ‖w‖² solved by a second-order Taylor expansion; key knobs `eta`/`max_depth`/`subsample`/`colsample_bytree`/`gamma`/`lambda`/`alpha`; the cache-aware `xgb.DMatrix`; `early_stopping_rounds` and `xgb.cv` for the optimal round count; importance by gain/cover/frequency; DART tree dropout; LightGBM's histogram binning and leaf-wise growth.
- **Neural Networks (keras)** — `keras3` over Python Keras via `reticulate` (`install_keras()`); the Sequential API (dense + dropout stacks) and the Functional API for multi-input/output/shared layers; activations ReLU (hidden) vs sigmoid/softmax (output); loss selection (binary/categorical/sparse-categorical cross-entropy, `mse`); callbacks — `callback_early_stopping(restore_best_weights = TRUE)` as the key regulariser, `reduce_lr_on_plateau`, `model_checkpoint`; `tfruns` experiment tracking; `parsnip::mlp() |> set_engine("keras")` to embed a network in a tidymodels pipeline.
- **Model Interpretation (SHAP)** — Shapley values as fair coalition attribution satisfying the efficiency (Σφᵢ = f̂(x) − E[f̂]), symmetry, and dummy axioms; `shapviz` for exact tree SHAP on xgboost (beeswarm, bar, waterfall, force, dependence, interaction plots); `fastshap` for model-agnostic Monte-Carlo SHAP via a `pred_wrapper`; global (beeswarm) vs local (waterfall) interpretability; SHAP vs LIME (SHAP is globally consistent, LIME can be inconsistent for nearby points); partial dependence (`pdp`) and ICE plots, with a caution about correlated features.

**Key mental models:** Express the whole ML lifecycle through one swappable grammar (tidymodels or caret) so pipelines are reproducible and engines interchangeable. Keep preprocessing inside resampling and reserve the test set for a single final estimate — leakage is the cardinal sin. Early stopping and explicit regularisation tame boosting and neural nets. Explain models with axiom-satisfying SHAP rather than trusting leaderboard scores.

## 06. Advanced R

Advanced R engineering means writing code others can depend on: the metaprogramming that extends the language, proper object systems, C++ for CPU-critical work, and the web/API tooling that makes R models reachable from non-R systems. Non-standard evaluation — the mechanism behind `dplyr::mutate` — is the connective thread and the first topic demystified here.

**What's covered:**

- **Metaprogramming & NSE** — R is homoiconic: `x + 1` is a first-class language object. Base tools `quote`/`bquote`/`substitute`/`deparse` (`substitute` captures the caller's promise before it is forced); rlang's `expr`/`enexpr`/`enquo` producing quosures (expression AST + caller environment); `!!` (splice one expression) and `!!!` (splice a list); `{{ col }}` as shorthand for `enquo` + `!!`; `eval_tidy` against a data mask so column names shadow variables; `lobstr::ast` for the syntax tree and `as_label`/`as_name` for auto-generated labels; the primitives that power dbplyr's SQL translation and ggplot2's `aes()`.
- **R6 OOP** — R's four OOP systems (S3 single-dispatch, S4 multiple-dispatch/Bioconductor, R5 Reference Classes, R6); R6 for stateful objects with reference semantics — `self`/`private`/`active`, `initialize`, method chaining via `invisible(self)`; active bindings as computed properties (called without parentheses); inheritance via `inherit` and `super$`; `obj$clone(deep = TRUE)` for a real copy; the rule of thumb — S3 for data containers that integrate with generics (`[`, `format`, `print`), R6 for connections, caches, parsers, and accumulators where identity and mutation are intentional.
- **Rcpp & Performance** — profile first, Rcpp second; the throughput ladder (R loop ≈ 10⁷/s, vectorised R ≈ 10⁸/s, Rcpp ≈ 10⁹/s → roughly 100× over an R loop, 8–10× over vectorised R); `cppFunction` (inline) / `sourceCpp` (file) wired by the `// [[Rcpp::export]]` attribute; Rcpp types (`NumericVector`/`IntegerVector`/`List`/`DataFrame`) are GC-tracked `SEXP`s (no manual `PROTECT`); Rcpp Sugar (`sum`/`mean`/`ifelse`/`clamp`) for vectorised C++; RcppArmadillo for linear algebra (`arma::solve`, `A * B` matrix multiply, `A % B` element-wise); `Rcpp::stop`/`Rcpp::Rcout` for R-visible errors and output.
- **Shiny Applications** — the reactive programming model (declare how outputs depend on inputs; only downstream outputs recompute); the `ui`/`server` pair and `shinyApp`; `reactive()` (lazy, cached — shared expensive computation runs once) vs `observe`/`observeEvent` (side effects) vs `eventReactive` (button-gated); `isolate()` to read a value without subscribing; modules (`moduleServer` + `NS(id)`) for reusable namespaced components; `bslib` theming with `thematic::thematic_shiny()`; `shinytest2` snapshot testing; deployment via `rsconnect::deployApp` (shinyapps.io / Posit Connect) or Docker + shiny-server.
- **Plumber REST APIs** — Flask-style decorators (`#* @get`, `#* @post`) that turn plain functions into HTTP endpoints; `<id>` path parameters plus query/body arguments injected as function args; the `req`/`res` objects (status codes, headers); JSON serialisation by default via jsonlite, with `@serializer csv`/`png`; filters as middleware (CORS, auth) that call `plumber::forward()`; auto-generated Swagger UI at `/__swagger__/` enriched with `@param`/`@response`; async endpoints via `future_promise` + `plan(multisession)`; deployment via the `rstudio/plumber` Docker image or `rsconnect::deployAPI`.

**Key mental models:** NSE and quosures are the one mechanism behind every tidyverse DSL — master capture (`enquo`/`{{ }}`) and splice (`!!`) and the magic becomes craft. Use R6's reference semantics only for genuinely stateful objects; keep data containers in S3. Shiny and Plumber both expose R through declarative graphs — a reactive dependency graph and annotated routes — and C++ via Rcpp is the last resort, only after profiling and vectorisation.

## Cross-Cutting Mental Models

A handful of ideas recur across every section and explain why R feels the way it does.

1. **Everything is a vector, and vectorisation is the performance model** — R has no scalars; arithmetic dispatches to C-level loops, so making R fast means replacing R-level loops with vectorised calls (and only then `data.table` or Rcpp), never micro-optimising the loop body.
2. **Copy-on-modify, with two deliberate exceptions** — vectors and lists copy on write (cheap to read, doubling memory on edit), while environments and R6 objects have reference semantics — the same distinction that underlies both closures and stateful OOP.
3. **Tidy data plus one consistent grammar** — dplyr, ggplot2, tidymodels, and fable are all data-frame-in/data-frame-out and pipe-composable, so once you internalise tidy data and the pipe the entire stack reads the same way.
4. **Non-standard evaluation is the connective tissue** — data masking lets you write bare column names in dplyr and ggplot2; `{{ }}`, `.data[[ ]]`, and quosures make it safe inside your own functions, and the very same machinery powers dbplyr's SQL generation and every R DSL.
5. **Measure, check, and explain before you trust** — profile before optimising, verify assumptions (regression diagnostics, R̂, proportional hazards, white-noise residuals) before trusting a model, keep preprocessing inside resampling to prevent leakage, and attribute predictions with axiom-satisfying SHAP rather than leaderboard scores.
