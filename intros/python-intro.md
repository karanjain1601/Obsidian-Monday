# Python Data & ML Stack: Introduction to All Topics

This document is a guided tour of the 7 modules in the Python notes library — a production-focused reference covering the complete Python data-and-ML stack, from language internals through scientific computing, visualization, deep learning, and LLM API engineering. Every page pairs conceptual explanations with KaTeX math, Mermaid diagrams, and interactive React demos.

---

## 01. Core Python

CPython internals, the object model, and the language features professionals rely on daily.

**What's covered:**

- **Syntax and Data Types** — Python's name-binding model (everything is a heap object; assignment binds a name to an object, not a copy); CPython object header (`ob_refcnt`, `ob_type`); `id`/`type`/`sys.getrefcount`. Numeric types: arbitrary-precision `int` (base-2³⁰ limbs), IEEE 754 `float` (machine epsilon ε ≈ 2.2×10⁻¹⁶, the `0.1 + 0.2` pitfall), `complex`, `Decimal`/`Fraction` for exact arithmetic. Small-integer cache (`[-5, 256]`) and string interning — what `is` really tests. Mutable vs immutable classification and the mutable default argument trap. Container internals: `list` as a dynamic pointer array (amortised O(1) append); `dict` as a compact insertion-ordered open-addressed hash table (load factor < 2/3); `set`/`frozenset` for O(1) membership. Comprehensions (list, set, dict, generator), walrus operator (`:=`), chained comparisons, truthiness/falsy values.

- **Functions and Closures** — Functions as first-class objects (`__code__`, `__defaults__`, `__closure__`). Argument grammar: `*args`, `**kwargs`, positional-only `/` (PEP 570), keyword-only `*` separators. Closures via cell objects (`co_freevars`, `nonlocal`); the late-binding gotcha in lambda loops and the default-argument snapshot fix. Decorators as `f = decorator(f)` syntactic sugar; `functools.wraps` for metadata preservation; three-level nesting for argument-taking decorator factories. `functools` toolkit: `lru_cache`/`cache` (LRU memoisation), `partial` (argument freezing), `reduce` (folding). Generators: `yield`, lazy O(1) memory vs O(n) list, `yield from` delegation. Coroutine protocol: `send`/`throw`/`close`, bidirectional generators.

- **OOP and Metaclasses** — `__new__` (allocator) vs `__init__` (initialiser); when to override `__new__` (immutable types, singletons). Dunder methods: `__repr__`/`__str__`, `__eq__`/`__hash__` contract (`a == b` implies `hash(a) == hash(b)`), `__lt__` + `functools.total_ordering`, `__call__`. Attribute lookup chain: `__getattribute__` (all accesses) vs `__getattr__` (fallback). Descriptors: data descriptors (have `__set__`, beat the instance dict) vs non-data (yield to it); `__set_name__` (3.6+); `property` as a built-in data descriptor. `__slots__`: replaces per-instance `__dict__` with a C-level array (40–60% memory reduction). MRO and C3 linearization: subclass-before-parent, base-order-preserving, monotonic — diamond example worked through. Metaclasses: `type` is the default metaclass; custom metaclasses intercept class creation (`__new__`/`__init__`/`__prepare__`); ORMs and plugin registries as canonical use cases. `__init_subclass__` as a lighter-weight alternative. `@dataclass`: `frozen`, `slots` (3.10+), `default_factory`, `__post_init__`.

- **Async and Concurrency** — The GIL: protects CPython reference counts, serialises bytecode, released during blocking I/O and by many C extensions (NumPy, `hashlib`); CPython 3.13 free-threaded build (PEP 703). Decision framework: asyncio vs threading vs multiprocessing. The `asyncio` event loop: single-threaded cooperative multitasking, `epoll`/`kqueue`/`IOCP`, coroutine suspends at `await`. `async def` / `await` / `asyncio.run`. `asyncio.create_task` and `asyncio.gather` for concurrent fan-out; `asyncio.TaskGroup` for structured concurrency (3.11+, `ExceptionGroup`). Executors: `ThreadPoolExecutor` for blocking I/O libraries, `ProcessPoolExecutor` for CPU-bound work, `run_in_executor` / `asyncio.to_thread`. Amdahl's Law: S(n) = 1/((1−p) + p/n), ceiling 1/(1−p). Practical rules: I/O + async-native libs → asyncio; I/O + blocking libs → threads; CPU-bound → processes.

- **Standard Library** — `collections`: `defaultdict`, `Counter` (multiset + `most_common`), `deque` (O(1) both-end ops; draining a plain list as a queue is O(n²)), `namedtuple`, `ChainMap`. `itertools`: lazy O(1)-memory pipelines — `chain`, `product`, `combinations`, `groupby` (must sort first), `accumulate`, `islice`/`cycle`; combinatoric count formulas. `pathlib.Path`: `/` join operator, `rglob`, replaces `os.path`. `contextlib`: `@contextmanager`, `suppress`, `ExitStack` for dynamic contexts. `typing`: `Protocol` (structural duck typing), `TypeVar`, `Optional`, `Literal`, `overload` — checked statically, ignored at runtime. `logging`: levelled handlers and formatters, lazy `%`-arg form, `logger.exception`. `pytest`: plain `assert` with introspection, `@pytest.mark.parametrize`, `yield`-fixtures.

## 02. NumPy

The foundational array library underlying pandas, SciPy, PyTorch, TensorFlow, and scikit-learn.

**What's covered:**

- **Array Fundamentals** — `ndarray` anatomy: `data` pointer (flat contiguous buffer), `dtype`, `shape`, `strides`. Element address formula: offset = Σᵢ sᵢnᵢ. C-contiguous (row-major) vs Fortran-contiguous (column-major) strides. Dtype system: `int8`/`int32`/`int64`/`float32`/`float64`/`complex128`/`bool`; structured dtypes (C-struct-like records); silent overflow hazards. Views vs copies: basic slicing returns a view (shared buffer); fancy indexing and boolean masking return copies. Checking with `.base` and `np.shares_memory`. Indexing: integer/slice (views), fancy integer arrays (copies, repeats allowed), boolean masking (copy, flattens to 1-D). Reshape/ravel/transpose as pure metadata rewrites (no data movement); `.contiguous()` forces a copy when needed.

- **Broadcasting and Vectorization** — Vectorization payoff: C loops with no boxing eliminate interpreter overhead (typically 50–100× faster). Broadcasting rules: align shapes from the right; compatible if dimensions are equal or one is 1; size-1 axes stretched via stride-0 (no data copied); output dimension is the maximum. `np.newaxis`/`reshape` to insert size-1 axes; `keepdims=True` for reduction-then-broadcast. Ufuncs: element-wise C-level functions with broadcasting and type promotion (`np.add`, `np.multiply`, `np.exp`); `out=` to avoid temporaries; `where=` for masked computation; `.reduce`, `.accumulate`, `.outer`. `np.vectorize` is a Python loop wrapper — not true vectorization.

- **Linear Algebra** — `@` operator (PEP 465) dispatches to BLAS `gemm`; batched matrix multiply via leading axes. Element-wise `*` vs matrix `@`. BLAS/LAPACK dispatch: `np.linalg.solve`/`svd`/`eig`/`qr`/`cholesky` compile to cache-blocked, SIMD, multithreaded OpenBLAS/MKL routines. `solve` vs `inv`: LU + back-substitution is faster and more numerically accurate than forming A⁻¹. Decompositions: SVD (A = UΣVᵀ, most robust, reveals rank and conditioning), QR, Cholesky (SPD only, ~2× faster than LU), `eig`/`eigh` (latter for symmetric: real eigenvalues, faster). Least squares: `lstsq` (SVD-based, stable for rank-deficient). Condition number: κ(A) = σ_max/σ_min; large κ means lost accuracy (log₁₀κ digits lost). `cond`, `norm`, `det`, `matrix_rank`.

- **FFT and Signal Processing** — DFT formula: Xₖ = Σₙ xₙ e^(−2πikn/N). FFT: Cooley–Tukey divide-and-conquer reduces O(n²) to O(n log n). NumPy API: `np.fft.fft`, `fftfreq`, `fftshift`, `ifft`, `rfft`/`rfftfreq`/`irfft` (real signals, half the output). Nyquist frequency fₙ = fₛ/2; aliasing: signals above fₙ fold back irreversibly. Spectral leakage from non-integer cycles; window functions (Hann, Hamming, Blackman) trade frequency resolution for sidelobe suppression. Convolution theorem: ℱ{x * h} = ℱ{x} · ℱ{h}, turning O(n²) direct convolution into O(n log n) FFT-based convolution.

- **Random and Statistics** — Generator architecture: PCG64 `BitGenerator` (faster, better statistical tests than Mersenne Twister, supports independent parallel streams) + `Generator`. `np.random.default_rng(seed)`. `SeedSequence.spawn` for independent parallel streams. Key distributions: `normal`, `uniform`, `integers`, `poisson`, `binomial`, `exponential`, `choice` (with weights, with replacement for bootstrapping). Descriptive stats: `mean`, `std`/`var` (default `ddof=0` = population; `ddof=1` for unbiased sample estimate), `median`, `percentile`/`quantile`; `nan*` variants for missing data. Central Limit Theorem: X̄ₙ → N(μ, σ²/n); standard error σ/√n (quadrupling n halves error). Bootstrapping: resample with replacement + recompute statistic for assumption-free confidence intervals.

## 03. Pandas

The workhorse for tabular data manipulation — ETL, financial time series, and ML feature engineering.

**What's covered:**

- **DataFrame Operations** — DataFrame as "dictionary of Series sharing one row Index"; `BlockManager` stores columns by dtype in consolidated 2-D NumPy arrays. Index types: `RangeIndex` (O(1) memory), `Index` (hash table, lazy), `DatetimeIndex`, `MultiIndex` (factorised: levels + codes). `loc` (label-based, inclusive stop) vs `iloc` (position-based, exclusive stop) vs `at`/`iat` (scalar fast paths). Boolean filtering: `&`/`|`/`~` with mandatory parentheses; `isin`, `between`, `query` (numexpr-backed, avoids intermediate arrays). Performance hierarchy: vectorised ops > `Series.map` > `DataFrame.map` > `apply`. `assign` for immutable method chaining; `pipe` for arbitrary functions. `SettingWithCopyWarning`: chained indexing is ambiguous — use single `df.loc[rows, cols] = value`; pandas 3.0 Copy-on-Write.

- **GroupBy and Aggregations** — Split-apply-combine paradigm. `groupby` is lazy: returns a `DataFrameGroupBy` holding integer group codes; `sort=False` and `observed=True` for speed with categoricals. `agg`: scalar per group — single function, list, per-column dict, or named aggregations (`out=("col", "func")` for flat column names). `transform`: broadcasts a group statistic back to original row positions (same length as input) — for demeaning, z-scoring, rank within group without a merge. `filter`: selects whole groups by a boolean predicate. `pivot_table` = groupby + reshape with `aggfunc` and `fill_value`; `crosstab` for frequency/proportion tables. `pd.Grouper` for time + category combinations.

- **Merge and Join** — Three operations: `pd.concat` (stack along axis, align perpendicular labels, NaN for missing), `df.merge` (SQL-style keyed join), `df.join` (merge defaulted to index). Join types: inner (intersection), left (all left keys), right, outer (union). Join output size: |A ⋈ B| = Σₖ aₖbₖ — sum of products, not sums; many-to-many can explode. `validate` parameter to assert cardinality (`"1:1"`, `"1:m"`, `"m:1"`) and raise `MergeError`. `indicator=True` adds a `_merge` column (`left_only`/`right_only`/`both`). `on`/`left_on`/`right_on` for column keys; `left_index`/`right_index=True` for index joins; explicit `suffixes` over default `_x`/`_y`.

- **Time Series** — Temporal types: `Timestamp` (instant, `datetime64[ns]`), `Timedelta` (duration), `Period` (span + frequency), `DatetimeIndex` (axis of instants). `pd.to_datetime` with explicit `format` for speed; `errors="coerce"` → `NaT`. Resampling as time-aware groupby: `resample("1min")` with `ohlc`/`sum`/`ffill`; `closed` and `label` flags for bar-edge conventions (wrong settings → lookahead bias in backtests). Rolling window: MAₜ = (1/w) Σ xₜ₋ᵢ. Expanding window (growing from start). EWMA: sₜ = αxₜ + (1−α)sₜ₋₁, α = 2/(span+1). `shift` (introduces NaN), `diff` (first difference), `pct_change`; always `shift` predictors before computing targets to avoid lookahead bias. Timezone handling: `tz_localize` (attach, no clock change) vs `tz_convert` (translate, wall clock shifts). Business-day offset aliases (`"B"`, `"W-FRI"`, `"BME"`, `"QE"`).

- **IO and Performance** — File format comparison: CSV (no schema, slow), Parquet (columnar, typed, zstd-compressed, column-prunable — recommended for production), Feather/Arrow IPC (fastest, zero-copy, light compression), HDF5 (queryable, partial reads). Categorical dtype: replaces repeated strings with integer codes + dictionary; saves ~50–60× when unique count ≪ row count. Numeric downcasting (int64→int8 = 8× smaller). Memory profiling with `df.memory_usage(deep=True)` and `df.info(memory_usage="deep")`. `query`/`eval` via numexpr: fused operations, no intermediate arrays; wins above ~100k rows. Chunked reading with `chunksize` for larger-than-memory files. PyArrow backend (`dtype_backend="pyarrow"`): native strings, proper nulls, zero-copy Arrow interop.

## 04. Visualization

The full Python visualization stack — from publication-quality static charts to live streaming dashboards.

**What's covered:**

- **Matplotlib and the Axes API** — Everything is an Artist; two kinds: containers (Figure, Axes) and primitives (Line2D, Patch, Text, Collection). Axes is the whole plotting region (not an axis); XAxis/YAxis are children. State-machine API (`plt.*`) vs object-oriented API (`fig, ax = plt.subplots()`) — prefer OO for composability and unambiguity. `plt.subplots(nrows, ncols, sharex, sharey)`; `GridSpec` for irregular multi-cell layouts; `tight_layout`/`constrained_layout`. Colormap families: sequential (`viridis`, `Blues`, `magma`), diverging (`coolwarm`, `RdBu`), qualitative (`tab10`, `Set2`). Perceptual uniformity: equal data steps → equal perceived brightness L*; `viridis` is monotonic and colourblind-safe; `jet` violates this badly. Log/symlog/logit axis scales. Figure size in inches × DPI = pixels; vector export (SVG/PDF) for print; raster (PNG) for web; `bbox_inches="tight"`.

- **Seaborn Statistical Plots** — Tidy (long) data as the API contract — one row per observation, one column per variable; `pandas.melt` to reshape. Figure-level functions (`relplot`, `catplot`, `displot`) own the Figure and enable faceting via `col`/`row`; axes-level functions (`scatterplot`, `boxplot`, `histplot`) draw into a caller-controlled `ax`. Decision rule: faceting → figure-level; single panel → axes-level. Categorical plots: `box` (quartiles + outliers), `violin` (KDE shape, reveals bimodality), `strip` (jittered raw points), `swarm` (non-overlapping), `bar` (mean + CI). `regplot`/`lmplot` with bootstrapped confidence bands; `lowess` non-parametric smoother. Distribution plots: `hist`, `kde`, `ecdf` (no tuning, hides nothing). KDE formula: f̂(x) = (1/nh) Σ K((x−xᵢ)/h); bandwidth h governs bias–variance trade-off (Silverman's rule). `pairplot`/`PairGrid` for all-pairs overview. `sns.set_theme` for global style/palette/context.

- **Plotly Interactive** — A Plotly figure is JSON: `{"data": [...traces...], "layout": {...}}` rendered by `plotly.js` with pan/zoom/hover/selection built in. Two APIs: Plotly Express (`px`) is a high-level factory returning a `go.Figure`; Graph Objects (`go`) for low-level control — they compose freely. `fig.to_dict()`/`fig.to_json()` for introspection. `update_layout`, `update_traces(selector=...)`, `update_xaxes`/`update_yaxes`. Template system (`plotly_white`, `plotly_dark`, `ggplot2`). `make_subplots` for grids; `hovertemplate` with `%{x}` placeholders; continuous colour via normalised scale. Animations as lists of frames. `write_html` (standalone page with embedded `plotly.js`); `write_image` (static via Kaleido). Dash integration via `dcc.Graph` + callbacks.

- **Bokeh and Streaming** — `ColumnDataSource` (CDS): shared reactive data table; mutating the CDS re-renders all bound glyphs — the core reactive model. Glyph methods: `line`, `scatter`/`circle`, `vbar`/`hbar`, `patch`/`varea`. `HoverTool` with `@column` field references. Linked interactions: shared CDS gives free linked brushing; shared `x_range` gives linked pan/zoom. Bokeh Server: keeps Python objects alive over a websocket; Python callbacks run on events and push model diffs to the browser. `source.stream(new_data, rollover=N)`: appends new rows and drops oldest for a fixed-window scrolling chart — the canonical live data pattern. `curdoc().add_periodic_callback(tick, ms)` for timed updates. Layouts: `row`/`column`/`gridplot`, `Tabs`/`TabPanel`.

- **Dashboard Design** — Dash architecture: layout tree (`html.*` + `dcc.*`) + reactive callbacks; `Output`, `Input` (triggers), `State` (read-only, no trigger); one `Output` per callback; chained callbacks resolved in dependency order. `Input` vs `State` distinction: a Submit button as Input triggers the callback; form fields as State are read without triggering. Panel's `@pn.depends` for implicit reactivity. Tufte's data-ink ratio: maximise data ink / total ink — erase gridlines, 3D bevels, redundant borders. Colour accessibility: Okabe–Ito / `"colorblind"` palettes; redundant encoding (shape + label + colour). Small multiples over spaghetti plots. Performance: clientside callbacks for cheap UI glue (no Python round-trip); `lru_cache` for expensive data loads.

## 05. PyTorch

The dominant research-and-production deep learning framework — dynamic computation graphs, autograd, and the path from training to deployment.

**What's covered:**

- **Tensors and Autograd** — Tensor as metadata (shape, stride, offset) over a flat `Storage`; element address = offset + Σₖ iₖsₖ. Contiguity requirement for `.view()`. Zero-copy NumPy bridge (`torch.from_numpy`, `.numpy()`). `requires_grad=True` triggers define-by-run recording: each op creates a tensor with a `grad_fn` pointing to a `Function` node, building a dynamic DAG. Leaf vs non-leaf tensors; `.is_leaf`. `backward()` applies the chain rule from output to leaves; gradients accumulate (sum over paths) — zero with `optimizer.zero_grad()`. `retain_graph=True` for multiple backwards. Reverse-mode autodiff computes the VJP x̄ = Jᵀȳ without forming J; cost is a small multiple of the forward pass — ideal for many inputs, scalar loss. `detach()` (severs graph, shares storage), `torch.no_grad()` (disables recording), `loss.item()` to avoid graph leaks. Custom `autograd.Function`: `forward` + `ctx.save_for_backward` + `backward` (VJP); verify with `gradcheck`.

- **Neural Network Modules** — `nn.Module.__setattr__` routes by type into `_parameters` (`nn.Parameter`), `_modules` (`nn.Module`), `_buffers` (`register_buffer`); `.parameters()` recurses through `_modules`. `forward()` vs calling the module — calling runs hooks. `state_dict()` for save/load by dotted name. Core layers: `nn.Linear` (y = Wx + b, physically `x @ W.T + b`); `nn.Conv2d` output shape: ⌊(n + 2p − k)/s⌋ + 1; `nn.LSTM` (gated cell + hidden state); `nn.MultiheadAttention` (softmax(QKᵀ / √dₖ)V); `nn.TransformerEncoderLayer`. Container classes: `Sequential` (auto-defines `forward`), `ModuleList` (registered list, you write `forward`), `ModuleDict` — plain Python `list` is invisible to `parameters()`. Weight initialisation: Xavier/Glorot (Var(W) = 2/(nᵢₙ+nₒᵤₜ)) for tanh/sigmoid; Kaiming/He (2/nᵢₙ) for ReLU. `train()`/`eval()` flip `self.training`: Dropout is active at train (identity at eval), BatchNorm uses batch stats at train (running stats at eval).

- **Training Loop** — `Dataset` (`__len__`/`__getitem__`) + `DataLoader` (batching, shuffling, `num_workers` prefetch, `pin_memory`, `collate_fn` for variable-length padding with `pad_sequence`). Loss functions: `MSELoss` for regression; `CrossEntropyLoss` fuses `LogSoftmax + NLLLoss` — feed raw logits, never pre-softmaxed output; numerically stable log-sum-exp. `BCEWithLogitsLoss` for binary. Optimisers: SGD; SGD+momentum; Adam (bias-corrected first/second moments, adaptive per-parameter LR); AdamW (decoupled weight decay — transformer default). LR schedulers: `StepLR`, `CosineAnnealingLR` (ηₜ = η_min + ½(η_max − η_min)(1 + cos(πt/T))). Gradient clipping: g ← g · min(1, c/‖g‖). Mixed precision (`torch.amp`): `autocast` runs in fp16/bf16; `GradScaler` scales loss to avoid underflow, unscales before optimizer step. Canonical five-step loop: forward → loss → `backward` → `step` → `zero_grad`.

- **GPU and CUDA** — Device-agnostic pattern: `device = torch.device("cuda" if ...)`, `model.to(device)`, `tensor.to(device)` (returns new tensor — must reassign). PCIe transfer bottleneck: `pin_memory=True` + `non_blocking=True` enables async DMA overlapping compute. Caching allocator: `memory_allocated` (live tensors) vs `memory_reserved` (held from driver); `empty_cache` frees only unused reserved blocks; fragmentation can OOM despite apparent free memory. `torch.cuda.synchronize()` before timing; `CUDA_LAUNCH_BLOCKING=1` for debugging async exceptions. CUDA Streams for overlapping independent work. `DistributedDataParallel` (DDP): one process per GPU, gradient all-reduce g̅ = (1/N) Σ gᵢ overlapped with backward (bucketed); `DataParallel` deprecated (GIL-bound, master-GPU bottleneck). `torch.compile`: TorchDynamo captures Python into an FX graph; Inductor generates fused Triton/C++/OpenMP kernels; ~1.3–2× speedup from one line. Training memory breakdown: weights + gradients + optimizer states (Adam = 2× params) + activations. Profiling with `torch.profiler`.

- **Model Deployment** — Deployment pipeline: train → export → optimize → serve. TorchScript: `trace` (records one executed path, no data-dependent control flow) vs `script` (compiles full TorchScript subset, preserves control flow); `save`/`load` for portable `.pt` artifacts. ONNX: `torch.onnx.export` with `dynamic_axes` for flexible dims; targets ONNX Runtime, TensorRT, OpenVINO. Quantization: affine mapping q = round(x/s) + z, dequantization x̂ = s(q−z); int8 = 4× smaller than fp32; three methods: dynamic (no calibration, weights only), static PTQ (calibration set), QAT (simulated during training — best accuracy). fp16 ≈ 2× smaller, near-zero accuracy loss, GPU default. TorchServe: `.mar` archive; `preprocess`/`inference`/`postprocess` handler lifecycle; dynamic batching for GPU utilisation. Hugging Face Hub: `from_pretrained`/`push_to_hub`; safetensors format (zero-copy, memory-mappable, no arbitrary code on load).

## 06. TensorFlow and Keras

Production-focused deep learning with Keras 3's multi-backend API, TFX ML pipelines, and TF Serving.

**What's covered:**

- **Keras API and Layers** — Three model-building APIs: Sequential (linear stack, fastest to write, no branching), Functional (symbolic `KerasTensor` DAG, multi-input/output/shared layers, introspectable — production default), Subclassing (imperative `call`, dynamic control flow — PyTorch-like). `Dense` layer: y = φ(Wx + b); weights created lazily on first call. Core layers: `Dense`, `Conv2D`, `LSTM`, `MultiHeadAttention`. Custom layers: override `build(input_shape)` (create weights with `add_weight`), `call(inputs)`, `get_config` (serialisation); `training` flag for Dropout/BN. Activation functions: ReLU (dead neuron problem), Sigmoid (vanishing gradients), Tanh (zero-centred, still saturates), GELU (x·Φ(x), smooth self-gating — modern Transformer default), Softmax. Regularization: L2/L1 weight penalties; Dropout (inverted dropout, identity at inference); BatchNorm (batch stats at train, running stats at eval). Keras 3: `KERAS_BACKEND` env var selects TensorFlow/JAX/PyTorch; `keras.ops` for backend-portable custom code.

- **Custom Models and Training** — `tf.GradientTape`: records ops on watched tensors; `tape.gradient(target, sources)` runs reverse-mode AD. `tf.Variable` auto-watched; constants need `tape.watch`; `persistent=True` for multiple `gradient` calls. Custom training loop: `model(x, training=True)` → loss → `tape.gradient` → `optimizer.apply_gradients(zip(grads, trainable_variables))`; stateful metrics with `update_state`/`reset_state`. Custom `Loss` subclass: override `call(y_true, y_pred)` (e.g. Focal Loss). Custom `Metric` subclass: override `update_state`/`result`/`reset_state` (e.g. streaming F1 Score with `tf.Variable` state). `@tf.function`: traces Python via AutoGraph (`if`/`while`/`for` → `tf.cond`/`tf.while_loop`), caches graph per input signature; retracing cost when shapes/dtypes/Python scalars change — fix with `input_signature` using `None` for flexible dims. Callbacks: `EarlyStopping`, `ModelCheckpoint`, `ReduceLROnPlateau`, custom lifecycle hooks.

- **TF Data Pipeline** — `tf.data.Dataset` as lazy, chained description — nothing executes until iteration. Core transforms: `map` (parse/augment, `num_parallel_calls=AUTOTUNE`), `filter`, `batch`, `shuffle` (buffer), `repeat`, `cache` (memory or file), `prefetch`. Ordering matters: shuffle before batch (else batch membership frozen); cache after deterministic parsing, before random augmentation; `prefetch` always last. TFRecord format: binary sequential, splittable, `tf.train.Example` protobuf serialisation; `interleave` for parallel file reads. Producer-consumer overlap with `prefetch`: serial cost N(t_io + t_compute) vs pipelined t_io + N·max(t_io, t_compute); goal is t_io ≤ t_compute. Advantage over PyTorch `DataLoader`: runs in C++ runtime, avoids GIL and pickling overhead.

- **Transfer Learning** — Two strategies: feature extraction (freeze backbone `trainable=False`, train new head — fast, low variance) vs fine-tuning (additionally unfreeze top blocks at low LR). `layer.trainable = False` removes weights from `trainable_variables`. Keras Applications (`ResNet50`, `EfficientNetB0`, etc.) with `include_top=False` and matching `preprocess_input`; `training=False` keeps frozen BatchNorm in inference mode. Two-phase schedule: (1) train head at normal LR (e.g. 1e-3), then (2) unfreeze top layers, recompile at 10–100× smaller LR (e.g. 1e-5). Must recompile after changing `trainable`. Catastrophic forgetting: large LR displaces pretrained weights far from their minimum — small LR stays in the neighbourhood. Discriminative (layer-wise) LRs: ηₗ = η_base · γ^(L−ℓ) — higher LR for task-specific top layers, near-zero for universal low-level filters. The same two-phase pattern applies in PyTorch.

- **TFX and Production** — TFX DAG: ExampleGen → StatisticsGen → SchemaGen → Transform (preprocessing graph embedded into the model, eliminating training/serving skew) → Trainer → Evaluator (metrics + blessing vs baseline) → Pusher. Each component writes typed artifacts to a metadata store for full lineage. Transform is the key correctness component; Evaluator gates deployment. SavedModel: directory of `saved_model.pb` + `variables/` + named signatures (`@tf.function` with `input_signature`); language-neutral. TF Serving: C++ server, REST (port 8501) + gRPC (8500, preferred for throughput); serves highest-version subdirectory automatically; server-side batching improves GPU utilisation. TFLite: flatbuffer format, tiny interpreter; int8 = 4× compression with calibration; dynamic-range (weights only) vs full integer (weights + activations) quantization. PyTorch analogues: TorchScript/ONNX ↔ SavedModel; TorchServe ↔ TF Serving; PyTorch Mobile/ExecuTorch ↔ TFLite.

## 07. OpenAI and LLM APIs

LLM API engineering — prompt architecture, semantic search, tool-use agents, stateful assistants, and batch inference at scale. Patterns generalise to Anthropic, Mistral, Azure OpenAI, and Google Vertex.

**What's covered:**

- **Chat Completions** — Stateless endpoint: you own the `messages` array and replay full history every turn; every re-sent token is re-billed; long conversations grow quadratically in cost — production systems truncate or summarise. `client.chat.completions.create`; `response.choices[0].message.content`; `response.usage`. Message roles: `system` (durable instructions, highest weight), `user`, `assistant` (prior turns for memory), `tool` (function results). Sampling via temperature-scaled softmax: pᵢ = e^(zᵢ/T) / Σⱼ e^(zⱼ/T); T→0 is deterministic, T=1 is raw model, T→∞ is uniform. `top_p` (nucleus sampling) — use temperature or top_p, not both. `frequency_penalty` / `presence_penalty` for repetition suppression. `stream=True`: iterate `delta.content` chunks; lower perceived latency; `AsyncOpenAI` for async streaming. Structured outputs: `response_format` with JSON Schema (`strict: True`) or `.parse()` with Pydantic models. `seed` for best-effort reproducibility; `logprobs` for token log-probabilities and confidence; `max_completion_tokens` caps output; `finish_reason`: stop/length/tool_calls/content_filter.

- **Embeddings and Similarity** — Embedding as dense vector in semantic space where geometric proximity encodes meaning. `client.embeddings.create` with batched input (up to 2048 strings per call). `text-embedding-3-small` (1536 dims) vs `-large` (3072 dims). Matryoshka representation learning: important information in leading dimensions, so the `dimensions` parameter truncates with minor accuracy loss — re-normalise after manual truncation. Similarity measures: cosine similarity (a·b / ‖a‖‖b‖), dot product, Euclidean distance (‖a−b‖² = 2 − 2(a·b) for unit vectors); OpenAI embeddings are pre-normalised so all three give equivalent ranking. Vector stores for ANN search: FAISS (`IndexFlatIP` for inner product), pgvector, Pinecone; ANN algorithms (HNSW, IVF) trade recall for sub-linear query time. RAG pipeline: chunk (≈500 tokens with overlap) → embed → store → embed query → ANN retrieve top-k → augment prompt → generate. Retrieval quality (chunking strategy, k, reranking) typically dominates generation-model choice.

- **Function Calling and Tools** — The model is an orchestrator — it emits a `tool_calls` request, never executes code itself. Tool schemas as JSON Schema in `tools=`; `description` fields drive tool selection; `"strict": True` for schema-conforming argument JSON; `arguments` is always a JSON string — always `json.loads`. Multi-turn tool loop: call model → if `finish_reason == "tool_calls"` → execute → append `tool` messages matching each `tool_call_id` → call model again until text answer. Two invariants: append the assistant `tool_calls` message before results; every `tool_call_id` must have exactly one matching `tool` message. `tool_choice`: `"auto"`, `"required"`, `"none"`, or force a specific function. Parallel tool calls: multiple entries in one `tool_calls` list — execute concurrently with asyncio, answer each `id`; `parallel_tool_calls=False` for sequential. Error handling: catch exceptions and return as a tool result string so the model can recover; cap loop iterations; validate arguments before execution.

- **Assistants and Threads** — Stateful API: server stores thread history and manages the context window — you never resend the transcript (opposite of chat completions). Object model: Assistant (reusable config: model, instructions, tools, files), Thread (persistent conversation container), Message (one turn), Run (one execution — ephemeral). `client.beta.assistants.create`, `client.beta.threads.create`, `messages.create`, `runs.create_and_poll`. Run state machine: `queued` → `in_progress` → `requires_action` (tool call pauses the run, awaiting `submit_tool_outputs`) → `completed`/`failed`/`cancelled`/`expired`. Polling (`create_and_poll`) vs streaming (`runs.stream` with `AssistantEventHandler`, `on_text_delta`, `on_tool_call_created`, `until_done()`). Built-in hosted tools: Code Interpreter (sandboxed Python runtime, billed per session) and File Search (managed RAG over a vector store — no manual embedding pipeline). `run_steps` for a full audit trail of each `message_creation` and `tool_calls` step.

- **Batch Processing** — Use case: throughput problems (offline classification, embedding millions of records, synthetic data generation, eval suites) — not latency-sensitive work. Five-step workflow: prepare JSONL (one request per line, unique `custom_id`) → upload file (`purpose="batch"`) → `client.batches.create` (`completion_window="24h"`) → poll status (`validating` → `in_progress` → `finalizing` → `completed`) → download output file + error file. `custom_id` for unordered result matching — results do not return in submission order. Cost: ≈50% of synchronous pricing; batch also has a higher enqueued-token ceiling for effective throughput. Trade-off: ~50% cost savings in exchange for up to 24h latency. Separate error file isolates failures; partial completion on `expired`; re-enqueue only failed `custom_id`s in a new batch. Decision rule: batch when no user is waiting, requests are independent, and volume is large (thousands+); stay synchronous/streaming for interactive, latency-sensitive, or tool-loop-dependent work.
